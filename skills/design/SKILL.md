# design: AI 티 안 나는 화면

사용자에게 하는 질문과 보고는 모두 **한국어**로 한다.

AI가 만든 화면은 "아무도 고르지 않은 기본값"이 쌓여서 티가 난다. 이 스킬은 기본값을 찾아내고, **내용에 맞춰 일부러 고른 값**으로 바꾼다.
새 화면을 만들 때는 3번(방향)부터, 기존 화면은 1번부터 한다.

아래에서 `<scripts>` = `<base directory>/../../scripts` (`shot.py` 캡처, `contrast.py` 대비 계산). Python은 항상 `sh <scripts>/py.sh`로 실행한다 (윈도우 스토어 스텁 회피).

## 1. 현재 화면 캡처

- 로컬 서버(프로젝트의 dev 서버, Jekyll은 `bundle exec jekyll serve`, 빌드된 정적 폴더는 그 안에서 `sh <scripts>/py.sh -m http.server`)나 배포 주소를 데스크톱·모바일로 캡처한다:
  ```sh
  sh <scripts>/py.sh <scripts>/shot.py <url> /tmp/before-home.png
  sh <scripts>/py.sh <scripts>/shot.py <url> /tmp/before-home-m.png --mobile
  ```
  다크 모드가 있으면 `--theme light`, `--theme dark`로 둘 다 찍는다 (안 주면 이 컴퓨터 설정을 따른다).
- 목록, 상세(글), 코드·표가 있는 부분처럼 성격이 다른 화면을 하나씩 찍는다. 캡처는 Read로 보고 사용자에게도 보여 준다.
- 테마·UI 프레임워크를 쓰면 무엇을 쓰는지, 덮어쓰기 지점(커스텀 CSS, head 삽입 include, 테마 변수)을 먼저 찾는다.

## 2. 진단: AI·템플릿 티 체크리스트

캡처와 코드를 보고 해당하는 항목만 근거(어느 화면, 어느 요소)와 함께 적는다.

| 티 나는 것 | 왜 티가 나나 | 대신 |
|---|---|---|
| 보라·파랑 그라디언트, 그라디언트 글자, 네온 강조 | 생성 도구의 첫 기본값 | 중립색 + 강조색 하나. 강조는 링크·현재 위치·핵심 수치에만 |
| 모든 것을 둥근 카드(그림자·테두리)로 감쌈, 카드 안에 카드 | 위계를 상자로 해결 | 크기·굵기·여백·구분선으로 위계. 상자는 정말 묶어야 할 때만 |
| 가운데 정렬 히어로 + 큰 제목 + 부제 + 버튼 두 개 | 랜딩 템플릿 그대로 | 왼쪽 정렬, 첫 화면에 실제 내용(최근 글, 제품 화면) |
| 아이콘 + 제목 + 설명 3열 그리드 | 기능 소개 템플릿 | 실제 스크린샷·예시·코드로 보여 주기, 또는 목록 |
| 메뉴·메타 정보마다 아이콘, 이모지 아이콘 | 장식이 정보를 흉내 냄 | 글자만. 아이콘은 뜻이 글자보다 빠를 때만 (검색, 닫기) |
| 폰트 하나(Inter, 시스템 고딕)로 전부, 굵기 차이 없음 | 고르지 않은 흔적 | 읽는 글과 UI 글꼴을 나눔(예: 본문 세리프 + UI 고딕 + 코드 고정폭) |
| 회색 바탕에 회색 글자, 흐린 본문, 안 보이는 아이콘 | "세련돼 보이는" 저대비 | 본문 4.5:1, 아이콘·입력창 테두리 3:1 이상 (`contrast.py`). 코드 블록처럼 바탕이 다른 곳은 그 바탕으로 따로 잰다 |
| 모든 간격이 같음, 모든 섹션 높이가 같음 | 리듬 없음 | 간격 단계를 정하고 묶을 것은 좁게, 나눌 것은 넓게 |
| 반투명 블러(glass), 떠 있는 그림자, 과한 둥근 모서리 | 2020년대 생성 화면의 표지 | 불투명 배경, 그림자 없음, 모서리 0~4px |
| 스크롤마다 페이드인, 모든 요소 hover 애니메이션 | 움직임이 내용을 가림 | 움직임은 상태 변화(열림, 저장됨)에만 |
| 테마 기본 장식: 코드 블록의 창 버튼 점 3개, 알약 모양 태그, 원형 아이콘 버튼 | 테마를 그대로 둔 흔적 | 빼거나 글자로 (`#태그`) |
| 같은 정보를 두 번 (홈 목록 옆에 "최근 글" 위젯) | 위젯을 다 켜 둠 | 하나만 남김 |
| 제목을 줄 수로 자르고 `…` | 카드 높이를 맞추려는 장치 | 목록의 제목은 자르지 않는다 (요약은 2줄 정도로 잘라도 된다) |
| "더 빠르게, 더 쉽게" 류 문구, 의미 없는 배지, 가짜 수치·후기 | 내용 없는 채움 | 실제 내용이 없으면 그 칸을 없앤다 |

한국어 화면은 추가로: 단어 중간 줄바꿈(`word-break: keep-all` 없음), 한글이 없는 영문 웹폰트만 지정해서 한글이 시스템 폰트로 섞임, 한 줄이 너무 긺(본문 폭 약 35~45자).

진단 결과는 "가장 티 나는 것 3개"를 먼저 말하고 나머지는 표로 정리한다.

## 3. 방향 정하기 (질문)

AskUserQuestion으로 **방향 2~3개**를 preview(ASCII 배치 + 글꼴·색 한 줄)와 함께 보여 준다. 추천을 첫 번째에 둔다.
방향은 내용에서 만든다. 누가, 무엇을, 얼마나 오래 보는가 (예: 긴 기술 글 → 읽기 위주 "종이 노트", 대시보드 → 밀도 높은 표 위주).
필요하면 범위도 함께 묻는다: 테마·프레임워크 유지 + 덮어쓰기(추천) / 직접 만들기.

## 4. 토큰 먼저

화면을 고치기 전에 값을 정해서 CSS 변수(또는 테마 변수) 한곳에 모은다.

- **색**: 바탕, 진한 바탕(코드·표 머리), 글자, 흐린 글자, 구분선, 강조 1개. 글자 조합은 모두 `contrast.py`로 확인한다:
  ```sh
  sh <scripts>/py.sh <scripts>/contrast.py 26241f f6f2ea 6a645a f6f2ea
  ```
  장식용 구분선은 대비 기준에서 빠지지만, 입력창 테두리·아이콘 버튼처럼 기능이 있는 선과 아이콘은 3:1 이상이어야 한다. 장식용 흐린 색을 글자에 쓰지 않는다.
  테마가 따로 정한 색(코드 주석·줄 번호, 아이콘, 버튼)도 새 바탕에서 다시 잰다. 바탕만 바꾸면 이 색들이 기준 밑으로 떨어진다.
- **글꼴**: 읽는 글, UI(메뉴·날짜·표), 코드. 한국어 웹폰트는 Google Fonts처럼 글자 범위별로 나눠 받는 것을 쓴다.
- **크기·간격**: 본문 크기·줄 간격(한국어 본문 1.7~1.85), 간격 단계 3~4개, 본문 최대 폭.
- **모서리·그림자**: 숫자 하나로 통일 (대개 0~4px, 그림자 없음).

## 5. 적용

- **테마·프레임워크를 쓰면 포크하지 않고 덮어쓴다.** 순서: 테마 변수 → 커스텀 CSS → head 삽입 지점(폰트) → 마크업 파일 덮어쓰기는 마지막 수단 (업데이트를 못 받게 됨).
- 덮어쓰기가 안 먹으면 **빌드된 CSS에서 같은 속성을 가진 테마 규칙을 grep해** 우선순위를 비교한다. 자주 지는 경우:
  - 변수: Chirpy는 `:root[data-bs-theme=light]`에 변수를 건다 → `html`로는 못 덮고 `:root[data-bs-theme]`로 덮는다.
    모드를 고르지 않은 방문자(시스템 따름)는 속성이 없어서 `:root:not([data-bs-theme])` + `prefers-color-scheme`로 따로 걸린다 → 둘 다 덮는다
  - 중첩: 테마가 `#post-list .card .card-body .card-title`이면 `.card`를 빼고 쓴 내 규칙은 진다 → 같은 깊이로 쓴다
  - 상태: `&:not(:focus-visible)` 같은 가상 클래스가 붙은 규칙은 같은 가상 클래스로 덮는다
  - 가상 요소: 글자를 `::after { content: attr(...) }`로 그리면 글꼴·크기도 `::after`에 준다
  고친 뒤에는 캡처로 실제 반영을 확인한다. 소스만 보고 "적용됨"이라고 하지 않는다.
- 테두리를 다시 그릴 때 테마의 `border: 0`은 style까지 지운다 → `border-bottom: 1px solid ...`처럼 style까지 쓴다.
- 기능(검색, 목차, 다크 모드 토글, 키보드 포커스 표시, 접근성 속성)은 지우지 않는다. 숨기는 것은 장식과 중복 정보만.
- 방향 때문에 기능을 빼야 하면(예: 밝은 종이 방향이라 다크 모드를 끔) **적용 전에** 묻는다. 대안(다크 팔레트도 같은 방향으로 만들기)을 함께 제시한다.

## 6. 검증

1. 1번과 같은 화면을 다시 캡처해 **전/후를 나란히** 보여 준다 (데스크톱, 모바일, 코드·표 부분).
2. 2번 체크리스트를 다시 돌려 남은 항목을 적는다. 일부러 남긴 것은 이유를 적는다.
3. 프로젝트의 빌드·검사(링크 검사, 린트)를 실행한다.
4. T1 이상이면 harness 절차대로 독립 검증을 받는다. 검증자에게는 전/후 캡처 경로와 이 체크리스트만 주고, 내 결론은 주지 않는다.

## 7. 마무리

- push·배포는 harness 공통 규칙 "승인", "push와 배포"를 따른다. 승인을 받을 때 미리보기로 로컬 캡처(전/후)를 보여 준다.
- 이번 화면에서 새로 찾은 "티 나는 것"이 있으면 이 스킬의 체크리스트에 추가하자고 제안한다 (kit 레포 개선 사항이면 /kit:feedback).
