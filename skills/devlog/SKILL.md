# devlog: 작업 로그

여러 컴퓨터와 프로젝트의 로그를 나중에 기계적으로 모아 분석(/weekly)하고 문서(/docs)를 만들기 위한 기록이다.
**형식을 정확히 지킨다.** 특히 제목 줄.

## 파일

- 위치: `<레포 루트>/docs/devlog/YYYY-MM.md` (한 달에 파일 하나, 날짜는 로컬 날짜 기준)
- 파일이 없으면 첫 줄을 `# Devlog YYYY-MM`으로 만든다.
- 새 항목은 파일 **맨 아래**에 추가한다 (오래된 것이 위).
- `docs/devlog/`가 없으면 kit 프로젝트가 아니므로 `/kit:init`을 먼저 안내하고 멈춘다.

## 항목 형식

```markdown
## 2026-10-14 · macOS · feat/social-login

**요약**: 구글 소셜 로그인 연동, 토큰 갱신 구조 분리

**한 일**
- 구글 OAuth 콜백 API 구현
- 토큰 갱신 로직을 auth-service로 분리

**결정 & 이유**
- 세션 대신 JWT 사용 → 모바일 앱과 같은 인증을 공유하기 위해

**문제 & 해결**
- 콜백 URL 불일치 오류 → Amplify 환경변수에 운영 도메인 누락

**커밋**
- a1b2c3d feat(auth): 구글 소셜 로그인 추가
- d4e5f6a refactor(auth): 토큰 갱신 로직 분리

**다음 할 일**
- [ ] 애플 로그인
- [ ] 토큰 만료 테스트 작성

**TIL**
- my-notes/til/2026-10-14-oauth-callback.md
```

규칙:
- **제목 줄**: `## YYYY-MM-DD · OS · 브랜치` 고정. OS는 `macOS` / `Windows` / `Linux` 중 하나 (`uname -s` 등으로 확인). 브랜치는 `git branch --show-current`, detached면 `detached`.
- **섹션 이름과 순서는 위와 똑같이** 쓴다. 내용이 없는 섹션은 통째로 생략한다. 요약은 항상 쓴다.
- **결정 & 이유**가 가장 중요하다. 대화에서 "A 대신 B로 하자" 같은 선택이 있었다면 반드시 이유와 함께 남긴다.
- **커밋**: 해시는 7자리. 이 항목에 해당하는 커밋만 적는다.
- **TIL**: 이번 작업 중 /kit:til 로 저장한 메모 경로.
- **다음 할 일**: 체크박스 형식. 다음 세션 시작 때 SessionStart 훅이 이 섹션을 읽어 Claude에게 알려준다.
- 내용은 한국어, 코드·명령·파일명은 원문 그대로. 회사 기밀(비밀번호, 키, 고객 정보)은 적지 않는다.
- 쓸 내용이 커밋 한두 개뿐인 짧은 작업이면 **요약**과 **커밋**만 써도 된다.

## 절차

1. 정보 수집
   - 대화 내용: 무엇을 했고, 무엇을 결정했고, 어떤 문제를 겪었는지
   - 아직 기록되지 않은 커밋: `git log --since=3.days --no-merges --format="%h %s"` 중 `docs/devlog/*.md`에 해시가 없는 것 (`docs(devlog)` 커밋은 제외)
   - 이전 항목의 **다음 할 일** 중 이번에 끝낸 것이 있으면 이번 항목의 한 일에 반영한다 (이전 항목은 수정하지 않는다)
2. **같은 제목 줄**(같은 날짜·OS·브랜치)의 항목이 파일 맨 끝에 이미 있으면 새로 만들지 않고 그 항목에 내용을 합친다.
3. 작성한 항목을 사용자에게 보여주고 파일에 쓴다. 사용자가 수정을 원하면 반영한다.
4. 로그 파일만 커밋한다 (다른 스테이징된 변경은 건드리지 않음):
   `git commit -m "docs(devlog): YYYY-MM-DD 작업 로그" -- docs/devlog/YYYY-MM.md`
   (파일이 새로 생겼으면 먼저 `git add docs/devlog/YYYY-MM.md`)
