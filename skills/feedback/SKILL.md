# feedback: kit 개선 아이디어 남기기

다른 프로젝트에서 코딩하다가 "kit의 이 부분을 고치고 싶다"는 생각이 들 때 쓴다.
**지금 하던 작업을 끊지 않는 것이 최우선이다.** 질문 없이 이슈를 만들고 한 줄로 보고한 뒤 원래 작업으로 돌아간다.
보고는 **한국어**로 한다.

## 1. 내용 정리

인자(`/kit:feedback devlog에 소요 시간도 기록하고 싶어`)와 **방금까지의 대화**에서 정리한다.

- **제목**: 무엇을 바꾸고 싶은지 한 줄. 앞에 대상 스킬이나 훅을 붙인다. 예) `[devlog] 소요 시간 항목 추가`, `[hook] git push 확인에서 태그 push 제외`
  - 대상: init, commit, devlog, plan, til, blog, check, release, weekly, feedback, hook, 새 스킬, 기타
- **본문**:

```markdown
## 원하는 것
무엇이 어떻게 바뀌면 좋겠는지

## 왜 (어떤 상황에서)
지금 작업 중에 무엇이 불편했는지. 구체적인 상황이 있어야 나중에 정확히 고칠 수 있다.

## 제안 (있으면)
대화에서 나온 구현 아이디어

---
환경: <OS> · <프로젝트 구분> 프로젝트 · <오늘 날짜>
```

## 2. 공개 저장소 주의 (반드시)

kit 저장소(`37writes/37writes-claude-kit`)는 **공개**다. 이슈도 누구나 볼 수 있다.

- 현재 레포 `CLAUDE.md` 프로필의 구분이 **회사**나 **대학원**이면: 프로젝트 이름, 회사명, 내부 코드, 경로, 주소를 쓰지 않는다. "회사 프로젝트", "ROS2 패키지"처럼 일반화한다.
- 어떤 경우든 비밀값, 개인 정보, 로컬 사용자 경로(`/Users/이름/`)는 쓰지 않는다.
- 개인 프로젝트는 레포 이름까지만 적어도 된다.

## 3. 이슈 만들기

본문은 heredoc으로 표준 입력에 넘긴다 (임시 파일 없이, 따옴표·줄바꿈 문제 없이):

```sh
gh issue create -R 37writes/37writes-claude-kit --label feedback --title "<제목>" --body-file - <<'BODY'
<본문>
BODY
```
- **`gh`가 없거나 로그인이 안 되어 실패하면** (회사 PC 등) 이슈 대신 로컬 대기 목록에 추가한다:
  `~/.config/37writes-kit/feedback-pending.md` 맨 아래에 `## <제목>` + 본문.
  다음에 kit 레포에서 세션을 시작하면 대기 목록이 있다고 알려준다. 그때 이슈로 옮기고 파일에서 지운다.

## 4. 보고 (한 줄)

```text
💡 kit 이슈 #12 등록 — [devlog] 소요 시간 항목 추가 (kit 세션에서 처리)
```

그리고 하던 작업으로 바로 돌아간다. 이 세션에서 kit 파일을 직접 고치지 않는다.
사용자가 "지금 바로 고쳐줘"라고 하면 그때만 kit 파일을 수정하고, kit 레포에서 따로 커밋한다.

## kit 세션에서 처리할 때

kit 레포에서 세션을 시작하면 SessionStart 훅이 열린 feedback 이슈와 로컬 대기 목록을 알려준다.
처리할 때는 `gh issue view <번호> -R 37writes/37writes-claude-kit`로 읽고, 고친 커밋 본문에 `Closes #<번호>`를 적는다.
push하면 이슈가 자동으로 닫힌다.
