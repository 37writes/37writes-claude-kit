- 블로그 프로필 사진 교체

**결정 & 이유**
- harness는 모델 호출 허용 → 프로필의 "작업 등급" 줄이 스킬로 안내해야 하므로. 대신 description을 짧게
- 등급은 영향 범위로, 워커를 띄울지는 변경 규모로 → 첫 실전(IAM 두 줄 + 배포)에서 T2인데 코드는 T0 수준이었음
- 워커는 Orca → 서브에이전트 → 단일 세션 순 → Orca가 없는 컴퓨터·프로젝트에서도 같은 절차를 쓰기 위해
- AGENTS.md는 init에서 만들지 않고 harness가 Codex 등 다른 에이전트를 처음 쓸 때 제안 → 모든 프로젝트가 Codex를 쓰지는 않음
- 상태 문서(STATE.md) 대신 기존 devlog "다음 할 일"을 Tracker 기록으로 사용 → SessionStart 훅이 이미 읽어 줌
- Orca가 있으면 워커 실행·메시지·대기·정리는 Orca orchestration 안내서에 맡김 → 처음 쓴 harness가 대기 시간·상태 정리를 따로 정해 Orca 규칙과 충돌했음. kit은 등급·계획·검증 기준·기록만 맡고, 작업 지시는 Orca Task spec 5항목, 보고는 `worker_done`, T2 승인은 `gate-create`
- plan 템플릿은 harness가 `../plan/SKILL.md`를 참조 → plan은 disable-model-invocation이라 Skill로 부를 수 없고, 템플릿 중복을 피하려고
- 블로그는 Chirpy 유지 + SCSS 덮어쓰기 → 검색·목차·PWA를 그대로 쓰고 테마 업데이트도 받기 위해
- 다크 모드 토글 유지, 같은 방향의 다크 팔레트 → 처음엔 `theme_mode: light`로 토글을 없앴는데 독립 검증에서 기능 제거로 지적, 사용자 선택
- 캡처는 gstack browse 대신 shot.py → browse 바이너리가 이 Mac에서 바로 종료(137), 다른 컴퓨터엔 gstack이 없을 수 있음

**문제 & 해결**
- 하네스 첫 실전의 교훈(관리자 키 로컬 테스트가 권한 누락을 가림, 로그엔 첫 권한만 찍힘) → harness 검증 단계에 실행 역할 기준 `simulate-principal-policy` 확인 추가
- 덮어쓴 CSS 변수가 안 먹음 → Chirpy가 `:root[data-bs-theme=light]`에 변수를 검. 시스템 따름 상태는 속성이 없어 `:root:not([data-bs-theme])`도 따로 덮어야 함
- 독립 검증이 우선순위 패배(제목 줄임, 원형 버튼, 코드 라벨 `::after`)와 저대비(검색 테두리 1.31:1, 복사 아이콘 1.34:1, 주석 3.99:1 등)를 찾음 → 같은 깊이 선택자로 덮고 색 재조정, 스킬에 규칙으로 반영
- headless Chrome 창이 500px보다 안 좁아짐 → 390px iframe으로 모바일 캡처
- `bundle install` 시 eventmachine 링크 실패(arm64e tapi) → `SDKROOT=$(xcrun --sdk macosx --show-sdk-path)`
