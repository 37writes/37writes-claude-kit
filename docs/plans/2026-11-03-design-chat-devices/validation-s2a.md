### 기기·상황 수행표

`적용 예정`은 이 보고서의 계획 설명이며 규칙의 결과 상태가 아니다. 실제 보고서에는 수행한 뒤 `적용`, 관련 있으나 못 보면 `미검증(이유)`, 무관함을 확인하면 `비해당(이유)`를 쓴다.

마지막 비선정 행의 문구는 예컨대 “비해당: 입력·시트가 없는 메뉴 문구 수정이며 해당 상태에 영향 없음”이다. 태블릿·넓은 화면을 못 봤다는 이유만으로 여기에 넣어서는 안 된다. `ego-validation.md:55`의 기본 폭 검사 유지와 `:70`의 영향 상황만 선택은 서로 다른 축이므로, 작은 수정이라고 기본 폭 검사까지 전부 삭제하지 않는다.

## 2. 프로필 없는 새 분석 대시보드

이번 모의 입력은 기존 화면·토큰·사용자 지정 방향도 없는 새 프로젝트로 구체화했다. 데이터는 가상의 항목 A/B/C, 기간, 값으로 구성한 합성 fixture를 사용한다. 공통 과업은 “기간과 항목을 골라 변화를 찾고 해당 상세를 연 뒤 돌아오기”로 둔다. 실제 숫자·업무 정보는 가져오지 않는다.

### 산출물과 순서

| 순서 | 산출물 | 규칙으로 수행할 내용 | 생략·미확정 |
|---|---|---|---|
| 1 | 기존 자산 조사와 방향 분류 | 기존 색·글꼴·부품·대응 문서가 없는지 확인하고 `새 방향 필요`로 분류 | 프로필이 없다는 사실만으로 기존 사용자 방향까지 없다고 단정하지 않는다. 이번 모의에서는 없음으로 명시 |

| 9 | 구현·한 디자이너 점검표 | 기준이 확보되면 구성 단계와 최종 검증에서 아래 역할별 비교를 한다. 차이와 허용 예외의 이름·이유를 프로필에 기록 | 새 화면을 자기 자신과 비교해 통일감 검증을 통과시킬 수 없음 |

첫 화면 하나뿐인 경우 `SKILL.md:35`는 “화면이 여럿이면”이라고 하지만 `:69`, `system.md:54`는 신규 화면의 기준 비교를 요구한다. 이번 모의에서는 기존 기준 화면이 없으므로 그 비교 부분을 완료했다고 할 수 없다. 나머지 토큰·상태·부품 내부 일관성 점검은 먼저 계획할 수 있다.

### 기기·상황 선택

| 행 | 실제 구현 후 수행할 핵심 조작 | 기록·제한 |

개인정보 처리: 사용자 정보가 보이는 브라우저 화면은 캡처하지 않는다. 외부 AI를 사용할 의무는 없으며 사용하더라도 공개 일반 질문만 보낸다. 프로젝트 데이터·내부 문서·캡처는 보내지 않는다. 제3자 캡처는 커밋하지 않고 보드에는 출처와 판단만 남긴다. 자기 프로젝트의 기준·시안 캡처에는 합성 fixture만 사용한다.

**모의 결과:** 레퍼런스 보드 → 비교 조건/fixture → 시안 → 선택표 → 사용자 선택/프로필의 순서는 도출할 수 있었다. 첫 기준 화면의 생성·고정은 명시되지 않아 이후 계산값 비교의 선행 조건을 확정하지 못했다. 이는 실제 사용자 선택이 아직 없다는 것과 별개의 문서 빈틈이다.

## 3. 독립적으로 선택한 실패·경계 시나리오

### 경계 1 — 관련 있는 터치·가상 키보드 검증을 실행할 수 없음

선택 이유: 표를 모두 채우는 형식은 지키면서도 “관련 있지만 못 봄”을 “비해당”으로 바꾸기 쉬운 경우다. 방향 선택과 메뉴 라벨 시나리오에 없는 도구 실패 경계를 확인한다.

| 단계 | 모의 입력과 수행 계획 | 규칙에서 도출한 결과 |
|---|---|---|
| 1 | 합성 대시보드가 텍스트 필터와 모바일 메뉴를 채택했다고 가정. ego의 터치 설정/이벤트가 거부되고 실기기도 없음 | 관련 행을 먼저 선정했으므로 선택하지 않은 무관 행으로 숨길 수 없음 |
| 2 | 가능하면 마우스·하드웨어 키보드, 소스, 기본 레이아웃·측정 결과를 따로 기록 | 정적 검증을 계속하되 터치 조작 성공을 주장하지 않음 |

### 경계 2 — 공개 레퍼런스 주소에 사용자 식별 쿼리가 포함됨

선택 이유: 캡처와 AI 입력을 금지해도 출처 URL 자체가 개인정보를 운반할 수 있다. 문서가 명시적으로 저장하도록 한 산출물의 경계를 고른 것이다.

## 7. 확인한 증거와 남은 일

| 확인 | 결과 |
|---|---|
| 시작 시 브랜치·HEAD·작업 상태 | 요청 브랜치와 대상 SHA 일치, 작업 디렉터리 변경 없음 |
| `git diff origin/main...HEAD -- skills/ README.md` | 지정된 일반 규칙과 README의 변경을 원래 규칙과 직접 대조 |
| CSS 3파일의 base/HEAD 바이트·해시 | 모두 동일 |
| 플러그인/marketplace JSON | 모두 0.17.0 |
| 대상 SKILL의 Markdown 상대 링크 7개 | 대상 파일 모두 존재, 방향 선택·한 디자이너 점검 절 제목 확인 |
| 실행 모델 확인 | `worker-show --dispatch ctx_ab56621ccd3d --json`에 provider model 필드 없음. 모델명은 세션 지침의 GPT-6로 표기 |

남은 일은 지휘 세션에서 지적 A를 반영하고 첫 화면 시나리오를 다시 대조하는 것, 지적 B의 보완 여부를 결정하는 것이다. 이 워커는 보고서 하나만 작성하며 규칙·README·기획서 본문 수정, 커밋·push·배포는 수행하지 않는다.
