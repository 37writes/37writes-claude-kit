# kit:design에 대화형 화면·기기 상황 매트릭스·레퍼런스 보드 추가

## 목표
사용자가 한 프로젝트에서 낸 디자인 요구를 kit:design의 공통 규칙으로 올린다. 어느 프로젝트에서든 다음 세 가지를 같은 방식으로 지키게 한다.
- 한 명의 디자이너가 만든 것 같은 통일감
- 주요 기기의 상황별 배치
- 여러 레퍼런스를 보고 방향을 고르는 절차

## 사용자 요구 (2026-11-03, 일반화)
- 디자인은 한 명의 디자이너가 작업한 것처럼 통일되고, 심플하고 명확해야 한다.
- 주요 기기의 상황별 배치를 반드시 고려한다. 폰 세로·가로, 키보드가 올라온 상태, 태블릿과 분할 화면, 노트북, 넓은 화면이 대상이다.
- 많은 레퍼런스를 확인해 여러 디자인 느낌을 비교할 수 있게 한다.
- 대화형(채팅) 화면에서 정한 것:
  - 기본 UI가 드러나지 않는 느낌으로 하고, 답의 형태는 질문에 따라 달라진다.
  - 답은 글만이 아니라 그래프·도형으로 빨리 이해시킨다.
  - 느리지 않다고 느끼게 하는 체감 속도 장치를 허용한다.
  - 모바일은 얇은 한 줄 바(☰ + 경로)를 쓴다.
  - 입력 영역이 화면을 차지하지 않게 한다. 키보드는 탭할 때만 올라온다.
  - 나중에 음성 대화를 붙여도 막히지 않게 한다.

## 범위
- 포함
  - `skills/design/SKILL.md`
  - `skills/design/references/` (새 참조 파일 포함)
  - `README.md`의 design 설명
  - 플러그인 버전
- 제외
  - 테마 색값과 CSS 자산 변경. 대화형 부품 CSS는 실제 프로젝트에서 검증한 뒤에 따로 다룬다.
  - 개별 프로젝트 파일 편집
  - 회사·서비스·고객사 이름. 공개 레포이므로 예시는 일반 도메인으로만 쓴다.

## 설계 (초안, 반박 후 확정)
1. **통일감 점검표** (`references/system.md`에 "한 디자이너 점검" 절로 추가)
   - 같은 역할에는 같은 부품을 쓰고, 간격 단계·글자 단계·모서리·선 두께는 각각 한 벌만 둔다.
   - 아이콘은 한 세트, 같은 굵기만 쓴다. 강조색은 한 역할에만 쓴다.
   - 상태 표현은 화면마다 같다(로딩, 빈 화면, 오류).
   - 문구 어조를 하나로 맞춘다.
   - 새 화면을 기준 화면 옆에 나란히 놓고 비교한다.
2. **기기·상황 매트릭스** (`references/devices.md` 신설, ego-validation이 이를 가리킨다)
   - 폭 목록이 아니라 "기기 × 상황" 칸으로 정의한다.
     - 기기: 폰 세로/가로, 태블릿 세로/가로, 분할 화면, 노트북, 넓은 화면
     - 상황: 키보드 올라옴, 시트·패널 열림, 메뉴 열림, 긴 내용
   - 칸마다 무엇이 보여야 하는지 기준을 둔다. 예: 키보드가 올라와도 대화 본문이 최소 N줄 보인다.
   - visualViewport와 `interactive-widget`의 사용 범위와 한계를 적는다. 가상 키보드는 실기기로만 증명된다.
3. **레퍼런스 보드와 방향 시안 절차** (SKILL.md 1절 보강)
   - 새 시각 방향이 필요할 때 거친다.
     - 레퍼런스 10곳 이상에서 주제별 패턴을 비교하고 "가져올 것 / 버릴 것"을 정한다.
     - 같은 시나리오로 방향 시안 3~4개를 만든다. 시안끼리는 테마만 다르고 위계·간격·동작은 같게 한다.
     - 사용자가 하나를 고른다.
   - 개인정보 규칙을 둔다. 로그인된 사용자 프로필에서는 사용자 기록이 보이는 화면을 캡처하지 않는다. 외부 AI에는 공개 일반 질문만 넣는다. 제3자 캡처는 커밋하지 않는다.
   - 기존 "새 작업마다 방향 3개를 다시 묻지 않는다" 규칙은 유지한다.
4. **대화형 화면 유형** (`references/conversational.md` 신설, system.md "화면 유형"에 한 줄 추가)
   - 입력창: 접힌 한 줄 → 탭하면 펼침. 스크롤하면 접히고 키보드가 내려간다. 고급 옵션은 숨긴다.
   - 헤더와 내비: 얇은 한 줄 바(☰ + 경로/제목 + 새 대화)
   - 답의 구성: 결론 → 시각 블록 → 근거 → 해석. 블록 종류와 "숫자는 데이터에서만" 원칙
   - 인용: 데스크톱은 옆 패널, 모바일은 하단 시트
   - 체감 속도 장치: 즉시 표시, 진행 줄, 골격 블록, 남은 시간·깊이 표시. 과장된 진행 표시는 금지한다.
   - 승인 카드, 오류·끊김·재연결
   - 음성 대비: 진입점 자리, 상태 3종, 말하는 동안 화면에 남는 것
   - 모바일 공간 예산: 입력·헤더가 차지하는 높이 상한
5. **버전**: 시스템 v1.0.0 → v1.1.0(규칙 추가, 토큰 변경 없음), 플러그인 0.16.0 → 0.17.0

## 결정 & 이유
- 대화형 패턴의 구체값은 실제 프로젝트(비공개)의 레퍼런스 조사와 시안 검증 결과로 확정한다. 근거 없는 규칙을 kit에 먼저 박지 않기 위해서다. 그래서 S2 구현은 그 프로젝트 S1(레퍼런스) 결과가 나온 뒤에 시작한다. 1~3번(통일감, 매트릭스, 레퍼런스 절차)은 프로젝트와 무관하므로 먼저 써도 된다.
- 테마와 CSS는 이번에 바꾸지 않는다. 기존 프로젝트의 자동 이관이 없다는 원칙을 지킨다.
- 레포가 공개이므로 사례는 "도메인 분석 에이전트 채팅" 같은 일반 표현으로만 쓴다.
