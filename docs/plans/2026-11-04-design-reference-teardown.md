# kit:design에 레퍼런스 해부(원칙·구조·인터랙션·질감·문구·시스템) 추가

## 목표
`/kit:design`이 숙련된 디자인 엔지니어처럼 레퍼런스 웹·앱을 깊게 뜯어보고(디자인 원칙, 정보 구조와 흐름, 인터랙션, 질감, 문구, 토큰 체계), 그 근거로 사용자의 과업에 맞게 바꾼 디자인을 프로젝트에 바로 적용하게 한다. 지금의 레퍼런스 보드는 겉모습·배치(탐색 배치, 정보 밀도, 목록·상세, 상태 표현, 색·글꼴)만 다루고 "가져올 것 / 버릴 것" 판단만 남겨서, 움직임·누를 때 반응·재질·문구 같은 "고급 디자이너 품질"의 차이를 옮길 절차가 없다.

## 사용자 요구 (2026-11-04, 원문. 회사 정보 없음)
- "15년차 된 고급 디자인 엔지니어로 레퍼런스 웹, 앱을 찾아서 디자인 스키마, 철학, UX 설계, 사용자 인터렉션 방식, 디자인 질감, 디자인에 관한 전반적인 내용을 조사하고 레퍼런스 디자인과 비슷하게 하면서 사용자의 니즈에 맞게 디자인을 바로 바로 나의 프로젝트에 적용할 수 있는 스킬 혹은 에이전트" → 현재 kit:design과의 차이(인터랙션·질감·흐름·문구 해부가 없음)를 설명했고 "kit 기획 T1으로 진행해줘".
- 앞선 요구: "UI의 아이콘, 도형, 버튼이 너무 AI가 만든거 같아. 고급 디자이너가 UI 작업하는 퀄리티가 나왔으면 해. … 레퍼런스꺼를 따라하도록 하자." "UI 관련해서는 예시 화면 만들어 보여주고 선택할 수 있게 해줘."

## 근거
- 한 비공개 프로젝트의 작업 화면에서 레퍼런스(공개 그래프 도구, 공개 부품 라이브러리)를 "따라하라"고 했을 때, 보드에 남은 것은 배치·색 판단뿐이었고 버튼의 누름 상태·전환 시간·그림자·선 굵기·아이콘 획은 작성자가 짐작으로 정했다. 결과가 "AI가 만든 티"라는 평가를 받았고, 부품을 다시 고칠 때 레퍼런스의 실제 값(높이, 모서리, 선 투명도)을 재고 나서야 정돈됐다.
- ego lite는 공개 페이지에서 계산된 스타일(`transition`, `box-shadow`, `backdrop-filter`, 글꼴 설정)과 `document.getAnimations()`를 읽을 수 있다. 네이티브 앱은 ego로 잴 수 없으므로 공식 디자인 가이드와 공개 자료로만 다룬다.

## 설계
0. **언제 쓰는가**: 새 방향·재설계(방향 선택), 사용자가 "X처럼/레퍼런스 따라" 요청, 같은 부품이 계속 "AI 티" 평가를 받을 때. 프로필이 있는 화면의 작은 수정에는 쓰지 않는다(정돈 규칙의 "끼어들지 않는 때"와 같은 기준).
1. **레퍼런스 고르기**: 넓은 보드(기존 약 10곳) 중 깊게 뜯어볼 것 3~5곳. 기준은 같은 화면 유형·같은 핵심 과업·같은 기기. 유명도가 아니라 사용자의 과업과 닮은 정도로 고르고, 고른 이유를 적는다. 로그인이 필요한 화면은 열지 않는다(기존 개인정보 규칙).
2. **여섯 축으로 해부** — 각 항목에 근거 종류를 붙인다: **실측**(ego 계산값·캡처), **문서**(그 제품이 공개한 디자인 가이드·부품 문서), **추론**(관찰에서 미루어 본 것, 사실처럼 쓰지 않음).
   - 원칙: 무엇을 우선하고 무엇을 거절하는가(밀도 대 여백, 장식 대 내용, 일관성 규칙). 공식 원칙 문서가 있으면 그것, 없으면 추론으로 표시.
   - 구조·흐름: 정보 구조, 탐색, 첫 과업까지의 경로와 조작 수, 빈·로딩·오류·권한 없음 상태.
   - 인터랙션: hover·press·focus·선택·펼침의 상태 변화(무엇이 바뀌는가), 전환 시간·가속 곡선, 피드백(즉시/낙관적/지연 표시), 키보드·터치 제스처, `prefers-reduced-motion` 대응.
   - 질감: 면의 층(바탕·면·띄운 면), 그림자 값, 선 굵기·투명도, 모서리, 흐림·재질, 글꼴(종류·굵기·자간·줄 높이·숫자 모양), 아이콘 획·격자.
   - 문구: 말투, 버튼 동사, 길이, 오류·빈 상태 문장.
   - 시스템: 간격 집합, 글자 단계 비율, 색 역할 수, 부품 변형 수.
3. **실측 절차**: ego Page에서 읽기 전용 `evaluate`로 역할별 요소의 계산 스타일을 읽고, hover·focus·press는 ego 조작 뒤 다시 읽어 전/후 차이를 적는다. 움직임은 `transition-*`·`animation-*`와 `getAnimations()`의 duration·easing. 같은 폭·같은 상태에서 잰다. 0개 매칭·canvas·shadow DOM은 미검사(정돈 점검과 같은 규칙).
4. **해부 시트**: 프로젝트의 `docs/design/references/<slug>.md`(또는 기존 디자인 문서 폴더)에 축별 표(항목 → 레퍼런스 값 → 근거 종류·출처 → 가져올 것/버릴 것 → 우리 과업에 맞춘 값과 이유). 제3자 캡처는 커밋하지 않고 출처 URL과 값만 남긴다.
5. **옮기기(번역)**: 레퍼런스를 복제하지 않고 원칙과 값의 범위를 옮긴다.
   - 사용자 과업·기기·밀도·접근성(대비 4.5:1/3:1, 누르는 영역 44, 움직임 줄이기)이 레퍼런스 값보다 우선한다. 바꾼 이유를 시트에 적는다.
   - 로고·브랜드 자산·고유 일러스트·유료 글꼴·특정 제품 화면을 그대로 베낀 배치는 가져오지 않는다. 글꼴·아이콘은 라이선스를 확인하고, 안 되면 비슷한 공개 대체를 적는다.
   - 결과는 프로필 토큰으로 고정한다: 기존 색·글꼴·간격 + 새 **움직임**(짧은·보통 시간, 가속 곡선, 줄이기 대응)과 **질감**(면 층, 그림자 단계, 선 굵기·투명도) 줄. 프로젝트 매핑 파일에 변수로 둔다.
6. **시안과 고르기**: 기존 방향 선택 2~4(시안 2~4개, 선택표)와 예시 화면으로 고르기를 그대로 쓴다. 해부에서 갈림길(예: 누를 때 "눌림 그림자" 대 "색 진하게")이 나오면 그 축으로 비교 이미지를 만든다. 움직임은 정지 캡처로 비교가 안 되므로 전/중/후 프레임을 나란히 붙이거나 짧은 녹화를 연다.
7. **검증**: 적용 뒤 같은 실측 절차로 우리 화면을 재서 해부 시트의 "우리 값"과 맞는지, 기존 5절 검증(터치·키보드·확대·움직임 줄이기)을 통과하는지. 독립 검토는 정돈 점검과 같은 입력(원래 요구·화면·레퍼런스 시트·프로필)으로.
8. **네이티브 앱 레퍼런스**: ego로 잴 수 없으므로 공식 가이드(플랫폼 디자인 가이드)와 공개 스토어 자료로 "문서/추론"만 쓰고, 실측 칸은 "미검사(네이티브)"로 둔다. 웹으로 같은 제품이 있으면 웹을 실측한다.
