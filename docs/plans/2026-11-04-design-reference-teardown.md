# kit:design에 레퍼런스 해부(원칙·구조·인터랙션·질감·문구·시스템) 추가

## 목표
`/kit:design`이 숙련된 디자인 엔지니어처럼 레퍼런스 웹·앱을 깊게 뜯어보고(디자인 원칙, 정보 구조와 흐름, 인터랙션, 질감, 문구, 토큰 체계), 그 근거로 사용자의 과업에 맞게 바꾼 디자인을 프로젝트에 바로 적용하게 한다. 지금의 레퍼런스 보드는 겉모습·배치(탐색 배치, 정보 밀도, 목록·상세, 상태 표현, 색·글꼴)만 다루고 "가져올 것 / 버릴 것" 판단만 남겨서, 움직임·누를 때 반응·재질·문구 같은 "고급 디자이너 품질"의 차이를 옮길 절차가 없다.

## 사용자 요구 (2026-11-04, 원문. 회사 정보 없음)
- "15년차 된 고급 디자인 엔지니어로 레퍼런스 웹, 앱을 찾아서 디자인 스키마, 철학, UX 설계, 사용자 인터렉션 방식, 디자인 질감, 디자인에 관한 전반적인 내용을 조사하고 레퍼런스 디자인과 비슷하게 하면서 사용자의 니즈에 맞게 디자인을 바로 바로 나의 프로젝트에 적용할 수 있는 스킬 혹은 에이전트" → 현재 kit:design과의 차이(인터랙션·질감·흐름·문구 해부가 없음)를 설명했고 "kit 기획 T1으로 진행해줘".
- 앞선 요구: "UI의 아이콘, 도형, 버튼이 너무 AI가 만든거 같아. 고급 디자이너가 UI 작업하는 퀄리티가 나왔으면 해. … 레퍼런스꺼를 따라하도록 하자." "UI 관련해서는 예시 화면 만들어 보여주고 선택할 수 있게 해줘."

## 근거
- 한 비공개 프로젝트의 작업 화면에서 레퍼런스(공개 그래프 도구, 공개 부품 라이브러리)를 "따라하라"고 했을 때, 보드에 남은 것은 배치·색 판단뿐이었고 버튼의 누름 상태·전환 시간·그림자·선 굵기·아이콘 획은 작성자가 짐작으로 정했다. 결과가 "AI가 만든 티"라는 평가를 받았고, 부품을 다시 고칠 때 레퍼런스의 실제 값(높이, 모서리, 선 투명도)을 재고 나서야 정돈됐다.
- ego lite는 공개 페이지에서 계산된 스타일(`transition`, `box-shadow`, `backdrop-filter`, 글꼴 설정)과 `document.getAnimations()`를 읽을 수 있다(안내서 API). 다만 정적 계산값(선언)과 실행 중 움직임(시점별 값)은 확인 범위가 다르고, 누름 유지·짧은 전환 포착은 S2에서 실제로 확인한다. 네이티브 앱은 ego로 잴 수 없으므로 공식 디자인 가이드와 공개 자료로만 다룬다.

## 설계
0. **언제, 얼마나 쓰는가** (위에서부터 먼저 맞는 것): ① 기존 프로필로 풀리면 해부하지 않는다(정돈 규칙의 "끼어들지 않는 때"와 같은 기준, 예: 라벨 오타·상태 색). ② 특정 부품·상태만 "레퍼런스처럼"이거나 그 부품이 계속 "AI 티" 평가를 받으면 **부분 해부**: 그 부품에 관련된 축만, 핵심 출처 1곳부터. ③ 새 방향·재설계(방향 선택)일 때만 **전체 해부**.
1. **레퍼런스 고르기**: 넓은 보드(기존 약 10곳)에서 **핵심 출처 1곳**으로 시작하고, 풀리지 않은 갈림길이 있을 때만 늘린다(전체 해부 상한 5곳). 기준은 같은 화면 유형·같은 핵심 과업·같은 기기. 유명도가 아니라 사용자의 과업과 닮은 정도로 고르고, 고른 이유를 적는다. 로그인이 필요한 화면은 열지 않는다(기존 개인정보 규칙).
2. **여섯 축으로 해부** — 여섯 축은 고르는 목록이다. 부분 해부는 관련 축만, 전체 해부에서 뺀 축은 "해당 없음 + 이유". 각 항목에 근거 종류를 붙인다: **실측**(ego 계산값·캡처), **문서**(그 제품이 공개한 디자인 가이드·부품 문서), **추론**(관찰에서 미루어 본 것, 사실처럼 쓰지 않음).
   - 원칙: 무엇을 우선하고 무엇을 거절하는가(밀도 대 여백, 장식 대 내용, 일관성 규칙). 공식 원칙 문서가 있으면 그것, 없으면 추론으로 표시.
   - 구조·흐름: 정보 구조, 탐색, 첫 과업까지의 경로와 조작 수, 빈·로딩·오류·권한 없음 상태.
   - 인터랙션: hover·press·focus·선택·펼침의 상태 변화(무엇이 바뀌는가), 전환 시간·가속 곡선, 피드백(즉시/낙관적/지연 표시), 키보드·터치 제스처, `prefers-reduced-motion` 대응.
   - 질감: 면의 층(바탕·면·띄운 면), 그림자 값, 선 굵기·투명도, 모서리, 흐림·재질, 글꼴(종류·굵기·자간·줄 높이·숫자 모양), 아이콘 획·격자.
   - 문구: 말투, 버튼 동사, 길이, 오류·빈 상태 문장.
   - 시스템: 간격 집합, 글자 단계 비율, 색 역할 수, 부품 변형 수.
3. **실측 절차**: ego Page에서 읽기 전용 `evaluate`로 역할별 요소의 계산 스타일을 읽는다. 같은 폭·같은 상태에서 잰다.
   - **상태 관찰 계약**: 기본 → hover → 누름 유지 → 해제 → 키보드 포커스를 **한 실행 안에서** 차례로 만들고, 표본마다 시각·`matches(":hover")`·`matches(":active")`·`matches(":focus-visible")`를 같이 적는다. 상태가 성립하지 않은 표본은 그 상태의 값으로 쓰지 않는다. 누름은 키 입력 API가 아니라 `mouse.down()`과 `try/finally`의 `mouse.up()`으로 만든다. 포인터 포커스와 키보드 포커스는 따로 잰다.
   - **움직임**: 선언값(`transition-*`·`animation-*`)과 실행 중 값(`getAnimations()`의 대상 요소·duration·easing·진행 시점)을 나눠 적는다. 선언을 읽은 것을 "움직임 실측"으로 올리지 않는다. 애니메이션 목록이 비면 "움직임 없음"이 아니라 "포착 못 함(미검증)"이다. JS·스크롤 구동, 가상 요소 움직임은 시각 관찰(전/중/후 프레임)이나 추론으로 표시한다.
   - 0개 매칭·canvas·닫힌 shadow DOM·교차 출처 스타일시트 원문은 미검사(정돈 점검과 같은 규칙). 호스트 박스만 잰 것과 내부 요소를 잰 것을 구분하고, 핵심 과업 부품이 미검사면 해부 성공으로 보고하지 않는다.
4. **해부 시트**: 프로젝트의 기존 디자인 문서 폴더에 짧은 결정 표(부분 해부는 디자인 문서 안 표 하나로 충분). 열: 항목 → 레퍼런스 값 → 근거(종류·출처·상태/시점·측정 조건·한계) → 기준 출처와 역할 → 채택/버림과 이유 → 우리 값. 출처끼리 값이 다르면 **기준 출처 하나**를 정하고 버린 대안을 적는다. 근거 없는 평균은 쓰지 않는다. 프로필에는 확정 토큰과 결정만 두고 시트는 링크한다. 제3자 캡처는 커밋하지 않고, 출처 URL은 기존 개인정보 규칙대로 정제하며, 수집한 문구·선택자에 개인 식별 정보가 있으면 기록하지 않는다.
5. **옮기기(번역)**: 레퍼런스를 복제하지 않고 원칙과 값의 범위를 옮긴다.
   - 사용자 과업·기기·밀도·접근성(대비 4.5:1/3:1, 누르는 영역 44, 움직임 줄이기)이 레퍼런스 값보다 우선한다. 바꾼 이유를 시트에 적는다.
   - 로고·브랜드 자산·고유 일러스트·유료 글꼴·특정 제품 화면을 그대로 베낀 배치는 가져오지 않는다. 글꼴·아이콘은 라이선스를 확인하고, 안 되면 비슷한 공개 대체를 적는다. 출처 링크는 재사용 허가의 증거가 아니다. 권리 근거가 불명확한 문구·코드·고유한 배치 조합은 관찰·추상화까지만 하고 구현은 독자적으로 쓴다. kit는 법적 적합성을 판정하지 않는다.
   - 결과는 프로필 토큰으로 고정한다. **기존 토큰 재사용이 먼저**(예: 테마의 띄운 면 그림자). 새 **움직임**(짧은·보통 시간, 가속 곡선, 줄이기 대응)·**질감**(면 층, 그림자 단계, 선 굵기·투명도) 토큰은 이름·소비 위치(어느 부품·상태)·기존 테마/모드와의 우선순위를 같이 적는다. 원본 자산은 그대로 두고, 매핑 파일은 변수 연결, 상태 선언(hover·누름·전환)은 프로젝트의 별도 어댑터 CSS나 기존 컴포넌트에 둔다. **소비하는 선언이 없는 토큰은 만들지 않는다.** system.md의 "매핑 파일에는 연결만" 문장과 이 위치를 맞춘다.
6. **시안과 고르기**: 기존 방향 선택 2~4(시안 2~4개, 선택표)와 예시 화면으로 고르기를 그대로 쓴다. 해부에서 갈림길(예: 누를 때 "눌림 그림자" 대 "색 진하게")이 나오면 그 축으로 비교 이미지를 만든다. 움직임은 정지 캡처로 비교가 안 되므로 전/중/후 프레임을 나란히 붙이거나 짧은 녹화를 연다.
7. **검증**: 적용 뒤 `채택 토큰 → 소비하는 선언/컴포넌트 → 계산값`을 같은 실측 절차로 추적해 시트의 "우리 값"과 맞는지 본다(변수만 선언된 경우는 실패). 같은 부품을 기본/hover/누름/disabled/키보드 포커스, 밝은/어두운/시스템 모드, 움직임 줄이기에서 확인하고, 기존 화면의 같은 역할 부품이 바뀌지 않았는지 대조한다. 기존 5절 검증(터치·키보드·확대)도 통과해야 한다. 독립 검토는 정돈 점검과 같은 입력(원래 요구·화면·시트·프로필)으로. 기존 선택표의 미관/과업 성공 분리는 그대로다.
8. **네이티브 앱 레퍼런스**: ego로 잴 수 없으므로 공식 가이드(플랫폼 디자인 가이드)와 공개 스토어 자료로 "문서/추론"만 쓰고, 실측 칸은 "미검사(네이티브)"로 둔다. 같은 제품의 웹을 재면 그것은 **웹 실측**이고 네이티브 증거가 아니다(플랫폼·버전·출처 종류를 나눠 적는다). 제스처·햅틱·시스템 전환은 웹으로 검증했다고 쓰지 않고, 스토어 정지 이미지로 흐름·시간을 단정하지 않는다.
