# 자리 비움(연속 작업) 모드 1단계

## 목표
사용자가 자리를 비운 동안 guard의 확인 창이 에이전트를 몇 시간씩 세우지 않게 한다 (newOpen, 2026-11-26 01:08~08:06, `cdk deploy` 확인 창에서 6시간 58분 정지). 모드 중에는 평소 `ask`할 명령을 `deny`+이유로 바꿔 아침 목록에 넣고, 에이전트는 다른 일을 계속한다. 같은 밤의 맥 잠들기(5회)는 `caffeinate`로 막는다.
**모드는 권한을 하나도 넓히지 않는다** (관제탑 임무 20261126-2, 사용자 결정 1).

## 범위
- **포함**: 새 `scripts/away.py`(on·off·status·report·hook), guard의 `ask`→`deny` 전환과 아침 목록, away 경로 보호, 훅 알림(UserPromptSubmit·SessionStart), `test_guard.sh` 판정 구분, 새 `test_away.sh`, harness·README·CLAUDE.md, 0.22.0
- **제외**: 허용 목록 통과·`cdk_gate.py`(2단계), AskUserQuestion 막기·Stop 훅(3단계), 메뉴 막대 앱, `pmset disablesleep`·배터리 모드, Write·Edit 도구 matcher(2단계), 다른 레포 수정

## 구현 전 확인 (더미 플러그인 `/tmp/away-probe`, Claude Code 2.1.332, 2026-11-26)
| 질문 | 결과 |
|---|---|
| `--dangerously-skip-permissions`·auto mode에서 PreToolUse `deny`가 이유와 함께 돌아가나 | 둘 다 명령은 실행되지 않았고 에이전트가 `PreToolUse:Bash hook error: <이유 원문>`을 받았다 |
| 사용자의 `! 명령`이 PreToolUse를 거치나 | 거치지 않는다 (대화형 세션에서 `! echo PROBE_DENY > bang.out`이 실행됐고 훅 로그 0줄. UserPromptSubmit도 안 불림). away 중에도 사용자는 `!`로 `away.py off`·배포를 실행할 수 있다 |
| 훅이 죽거나(exit 1) 시간 초과(제한 3초, 20초 sleep)면 | 명령이 그대로 실행됐다. guard는 best-effort이고, away 판정 오류는 평소 동작(`ask`)으로 떨어지게 짠다 |
| 플러그인 UserPromptSubmit의 `additionalContext` | 대화에 들어간다 (bypass·auto 둘 다) |

## 동작
1. 사용자가 `! sh <kit>/scripts/py.sh <kit>/scripts/away.py on --until 08:00` (또는 `--for 3h`).
   - 끝나는 시각 필수, 지금부터 최대 12시간. `--until HH:MM`은 다음에 오는 그 시각.
   - macOS 점검: AC 연결(`pmset -g batt`), 뚜껑 열림(`ioreg -r -k AppleClamshellState`, 키가 없으면 해당 없음). 배터리·뚜껑 닫힘은 시작 거부. 디스크 여유 5GB 미만은 경고만.
   - `caffeinate -i -s -t <남은 초>`를 분리된 자식으로 띄우고 pid를 상태 파일에 적는다. "뚜껑을 닫으면 잠듭니다" 한 줄.
   - 다른 OS: 전원 점검·절전 방지를 건너뛰고 그렇게 알린다 (모드는 켜진다).
   - 이미 켜져 있으면 새 끝 시각으로 바꾼다 (이전 caffeinate 종료 후 새로). 아침 목록은 유지.
2. 켜져 있는 동안
   - guard: 확인 이유가 있고 away가 유효(`now < until`)하면 `deny`. 이유: `자리 비움 모드(HH:MM까지): 이 명령은 사용자 확인이 필요해 아침 목록에 넣었습니다. 바꾸거나 감싸서 다시 시도하지 말고 다른 일을 계속하세요 (<원래 이유>)`. 아침 목록에 한 줄을 덧붙인다 (같은 레포·같은 명령은 `report`가 한 건으로 묶어 횟수를 센다).
   - 확인 이유가 없는 명령(`git status`)은 지금처럼 출력 없음. 상태 파일 없음·깨짐·만료·읽기 오류는 평소대로 `ask`.
   - UserPromptSubmit·SessionStart 훅(`away.py hook`): "HH:MM까지 자리 비움 모드: 확인이 필요한 일은 아침 목록으로, 되돌릴 수 있는 결정은 기본값으로, 다른 일을 계속". caffeinate가 죽었으면(재부팅 등) 한 줄 덧붙인다.
3. `off` (사용자 `!`): caffeinate 종료, `pmset -g assertions`에 그 pid가 없는지 확인, 상태 파일 삭제, 아침 목록 요약 출력. 해제를 확인하지 못하면 `caffeinate_released:false`.
   - 만료 시각에는 아무것도 실행되지 않는다: caffeinate `-t`가 스스로 끝나고 guard·훅은 `now >= until`이면 꺼진 것으로 본다. 남은 상태 파일은 `status`가 `expired:true`로 보여 주고 다음 `on`·`off`가 지운다.
4. 아침: `away.py report`로 목록을 본다 (`--clear`로 비움). 모드가 꺼져 있고 목록이 남아 있으면 SessionStart가 건수와 조회 방법만 알린다 (명령은 대화에 붙이지 않는다). 목록은 자동으로 다시 실행하지 않는다.

## 설계
- 신규 `scripts/away.py` (표준 라이브러리, guard가 import하는 모듈 겸 CLI)
  - 파일: `~/.config/37writes-kit/away/`(0700)의 `state.json`, `queue.jsonl`(0600), `state.lock`. "Mac 전체"는 정확히는 같은 HOME(계정) 기준이다.
  - `state.json`: `{version, id, started, until(epoch), caffeinate:{pid, args, lstart}, checks:[{name, ok, detail}]}`. `on`·`off`는 `state.lock`(flock, 최대 10초) 아래에서 읽기→caffeinate 교체→저장을 한다.
  - `queue.jsonl` 한 줄: `{key, ts, repo, reasons, command, session}`. guard는 잠금 없이 `O_APPEND`로 한 줄만 쓴다 (기다리는 구간이 없다). `command`는 공백을 정리하고 `이름=값`의 값 전부와 시크릿 패턴(AKIA…, `Bearer …`, PEM, `--password 값` 류)을 `***`로 가린 뒤, 220자를 넘으면 앞 150자 + ` … ` + 뒤 60자. `key`는 레포+명령 전체의 sha256 앞 16자 (원문은 저장하지 않음). `report`가 같은 `key`를 묶어 `{key, first, last, count, …}`로 보여 주고 `queue_count`는 묶은 뒤의 건수다.
  - 계약 (메뉴 막대 앱이 부른다. `test_away.sh`로 고정):
    - `on --until HH:MM | --for <3h|90m|1h30m> [--json]`, `off [--json]`, `status [--json]`, `report [--json] [--clear]`, `hook`(stdin 훅 입력)
    - 끝 코드: 0 성공(`status`·`report`·`off`는 꺼져 있어도 0), 1 예상 밖 오류, 2 인자 오류(끝 시각 없음·형식·12시간 초과), 3 시작 점검 거부(`on_battery`·`lid_closed`·`power_unknown`: macOS인데 전원을 읽지 못함), 4 절전 방지 시작 실패
    - `--json`이면 인자 오류까지 stdout에 JSON 하나만 낸다 (안내는 stderr)
    - `status --json`: `{ok, active, expired, until(ISO 8601, 시간대 포함), until_epoch, remaining_seconds, started, caffeinate:{pid, alive}, power:{source: ac|battery|unknown, lid: open|closed|unknown}, queue_count, checks}`. 꺼져 있으면 `active:false`이고 시각 값은 `null`.
    - `on --json`은 status와 같은 모양 + `warnings`, 실패는 `{ok:false, error:<코드 이름>, message}`. `off --json`: `{ok, was_active, caffeinate_released, queue_count}`. `report --json`: `{ok, count, items}`.
  - caffeinate pid는 `ps -p <pid> -o lstart=,args=`의 시작 시각과 인자가 기록과 둘 다 같을 때만 우리 것으로 본다 (재부팅 뒤 pid 재사용으로 남의 프로세스를 죽이지 않게).
- 변경 `scripts/guard.py`: `away_reasons`(`37writes-kit/away`를 건드리는 세그먼트가 `away.py` 밖이고 리다이렉트 없는 읽기가 아니면 이유 추가, `record_reasons`와 같은 방식), 마지막 판정은 세 갈래: 확인 이유 없음 → 출력 없음 / 상태를 못 읽거나 꺼짐·만료 → `ask` / 유효 → `deny` (목록 쓰기가 실패해도 `deny`, 이유에 "목록 기록 실패").
- 변경 `hooks/hooks.json`: SessionStart에 `away.py hook`(timeout 5), 새 UserPromptSubmit `away.py hook`(timeout 5). 꺼져 있고 목록도 비면 출력 없음.
- 변경 `scripts/test_guard.sh`: HOME 격리, 판정을 `none`(출력 없음)·`ask`·`deny`·`allow`·`error`(JSON 아님·끝 코드 ≠ 0)로 구분. 기존 `pass`는 `none`으로.
- 신규 `scripts/test_away.sh`: HOME 격리, `pmset`·`ioreg`·`caffeinate`·`ps`는 PATH 앞의 가짜 명령.
- 문서: harness "push와 배포"의 guard 줄 보강 + 짧은 "자리 비움" 절(170줄 이하), README(훅 표·사용법·한계), CLAUDE.md(구조·결정·테스트 줄), 버전 0.22.0.

## 결정 & 이유
- **상태는 Mac 전체 하나** (레포별 아님) → 사건의 구조가 지휘 탭 하나 + 여러 worktree의 워커였고, 등록 안 된 새 worktree·새 세션의 확인 창도 똑같이 멈춘다. 절전 방지도 Mac 단위다. 끝나는 시각이 "상태 파일 하나에서만" 나온다는 결정 4, 메뉴 막대 앱의 켜기/끄기 하나와도 맞는다. 모드가 권한을 주지 않으므로 넓게 걸어도 잃는 것은 "다른 레포에서도 확인 창 대신 거절"뿐이고, 사용자의 `!`는 훅을 거치지 않아 영향이 없다.
- **명령 원문은 앞 200자(가림)만** → 아침에 무엇이 막혔는지 알아보려면 명령이 보여야 한다 (GPT안의 "원문 제외"는 이유만 남아 사건 명령을 구분하지 못한다). 전체 원문 대신 해시로 중복을 가린다.
- **만료 뒤에는 평소 `ask`** → 임무의 판정 규칙 그대로. 끝 시각을 넉넉히 잡는 것은 사용자 몫이고 README에 적는다.
- **에이전트가 Bash로 `away.py on/off`를 실행하는 것은 막지 않는다** → 켜도 얻는 권한이 없고, 끄면 확인 창이 돌아오는 안전한 쪽 실패다. 같은 UID라 사람을 증명하지 못한다는 한계를 harness·README에 적는다 (결정 2).
- **Write·Edit 도구로 상태 파일을 고치는 것은 이번에 막지 않는다** → 얻는 것이 없고(위와 같음), matcher 확장은 2단계의 검증 기록 보호와 함께 한다.
- **AWS 자격 만료 점검은 넣지 않는다** → 프로젝트마다 다르다 (임무 범위).
- **구현은 지휘 세션이 직접, 검증은 Codex 워커** → 설계가 정해져 있고 파일이 서로 얽혀 있어 나눌 이득이 없다.

## 엣지 케이스 & 리스크
- 시계 변경·재부팅: 판정은 벽시계 `until`뿐이다. 재부팅하면 caffeinate는 죽고 모드는 `until`까지 유지된다 (훅 알림에 표시).
- 여러 세션의 guard가 동시에 목록을 씀 → 잠금 없이 `O_APPEND` 한 줄. 쓰기 실패 시에도 `deny`하되 이유에 "목록 기록 실패, 최종 보고에 직접 적으세요".
- 절전 방지는 전원 연결·뚜껑 열림이 유지되는 동안의 유휴 잠자기만 막는다. 켠 뒤 뚜껑을 닫거나 전원을 뽑아 잠드는 것은 막지 못한다 (README에 적는다).
- `deny`가 우회 압력을 키운다 (스크립트 파일로 감싸면 guard가 못 본다) → 막는 수단은 거절 이유·harness 문장·목록의 `count`뿐. 문서에 한계로 적는다.
- `cdk deploy` 정규식은 `echo "cdk deploy"`에도 걸린다 → away 중 불필요한 `deny`가 는다 (기존 오탐, 2단계 세그먼트 판정).
- 훅이 죽거나 시간 초과면 명령이 실행된다 (위 확인) → best-effort 한계로 문서화.
- 모드가 켜진 채 사용자가 돌아와 일하면 확인 창 대신 거절이 온다 → 거절 이유에 끝 시각이 보이고 `away.py off`로 끈다.

## 기획 반박
- 검토자: Orca 워커 codex, 모델 `global.openai.gpt-6.2-astra`(실행 요청값 + 워커가 보고서 첫 줄에 보고, `worker-show`에는 모델 값 없음), Task `task_14002fdd0971` · Dispatch `ctx_ac1b28601c5d`, 보고서 `docs/plans/2026-11-26-away-mode/rebuttal.md`
- 반례 1 전역 `queue.lock`에서 기다리다 훅 15초가 끝나면 `deny`여야 할 명령이 실행된다, "오류 → ask"와 "기록 실패 → deny"가 충돌 → **수용**. guard는 잠금 없이 한 줄 덧붙이기만 하고 중복은 `report`가 묶는다 (더 작은 해법도 같이 수용). 판정을 세 갈래로 고정하고 S3에서 목록을 쓸 수 없는 경우를 시험한다.
- 반례 2 `on`이 겹치면 caffeinate가 하나 남고 `off`는 성공으로 보인다, pid·인자만으로는 소유를 확인 못 한다 → **수용**. `on`·`off`를 `state.lock`으로 직렬화, 시작 시각(`lstart`)까지 대조, 해제 미확인이면 `caffeinate_released:false`. S2에 겹친 `on`·시작 시각이 다른 프로세스 시험.
- 반례 3 가림 패턴에 없는 인자 값(`License=…`)이 저장되고 다른 프로젝트 SessionStart에 붙는다, 200자 뒤에서만 다른 명령은 구분이 안 된다 → **부분 수용**. SessionStart·훅 알림은 건수와 조회 방법만. `이름=값`의 값은 전부 가리고 긴 명령은 앞 150 + 뒤 60자. "명령 종류·안전한 대상만 남기는 분류"는 기각: 명령마다 문법이 달라 guard가 대상을 믿을 만하게 뽑지 못하고, 사용자가 `report`로만 보는 0600 파일이다.
- 그 밖: `--json` 오류도 stdout JSON 하나, 만료 시각의 정리 주체, HOME 기준, `power_unknown` → 모두 수용 (동작·설계에 반영). 완료 기준에 "거절 뒤 같은 세션에서 독립적인 다음 일 하나가 끝남" 추가.
