# kit:design에 정돈 규칙(정렬·정보 예산)·예시 화면으로 고르기·정돈 점검 추가

## 목표
화면이 "AI가 만든 티"(정보 나열, 어긋난 선 끝, 같은 말 반복, 장식 부품)가 나지 않게 하는 규칙과 점검 절차를 kit:design에 넣는다. 사용자가 작업 중 `/kit:design`을 부르면 어느 프로젝트에서든 같은 기준으로 화면을 만들고, 기존 화면을 재서 고칠 곳을 찾고, UI 선택지는 예시 화면을 나란히 보여 주고 고르게 한다.

## 사용자 요구 (2026-11-04, 원문. 회사 정보 없음)
- "화면은 디자인하고 설계할 때는 선 끝단 일치하게 배치, 필요한 정보만 보여주기 등을 해야 하는데 너가 만든 UI는 정보 나열이 너무 많고 정신없고 전체적으로 조잡해. AI를 통해서 만든 티가 나. 이런 것을 고치는 작업을 한 다음에 마치 디자인 에이전트를 만들어서 앞으로도 계속 쓰고 싶어."
- "UI의 아이콘, 도형, 버튼이 너무 AI가 만든거 같아. 고급 디자이너가 UI 작업하는 퀄리티가 나왔으면 해. … 레퍼런스꺼를 따라하도록 하자."
- "내가 작업하면서 호출할 수 있는 스킬로 만들어 두고 싶어." → 위치는 새 스킬이 아니라 kit:design에 합친다(사용자 선택).
- "UI 관련해서는 예시 화면 만들어 보여주고 선택할 수 있게 해줘."

## 근거 (한 프로젝트에서 실측, 공개 레포라 이름·데이터는 쓰지 않는다)
지식 그래프 작업 화면(목록 · 그래프 · 상세 3열)을 위 규칙으로 정돈했다. 같은 상태·폭에서 ego lite로 잰 전/후:
- 영역별 글자 시작 x의 고유 값 3 → 1. 세 영역의 머리 줄 높이와 아래 선 y가 서로 다름 → 모두 48과 y=96.
- 태그·알약 154 → 0. 보이는 글자 덩어리 141 → 90. 글자 크기 4 → 3종, 굵기 4 → 2종. 강조색을 쓴 요소 57 → 3곳.
- 다른 모델의 독립 검토에서 줄이다 너무 뺀 곳(수치 근거로 가는 길, 폰의 "더 보기", 범위 표시)이 나와 되살렸다. 그래서 "빼기"에는 과업 확인이 반드시 붙어야 한다.
- 유형 색 노드 위에서 강조색으로 선택을 표시하면 명도 대비가 1.01~1.24배뿐이었다(색상으로만 구분).
- 사용자는 글로 된 선택지보다 예시 화면을 원했다.

## 설계
1. **정돈 규칙** (`references/layout-discipline.md`). 값은 출발점이고, 프로젝트 값은 프로필에 고정한다.
   - 정렬
     - 영역마다 세로 기준선은 둘까지다. 면의 왼쪽(검색 상자·선택 면·버튼 면)과 글자 시작(제목·탭 첫 글자·행 이름·본문)이다.
     - 오른쪽 끝(닫기·수·행 끝 화살표·도구)은 한 x에 둔다.
     - 이웃한 영역의 머리 줄은 같은 y와 같은 높이를 쓰고, 그 아래 선 하나가 끝까지 이어진다.
     - 버튼 안쪽 여백은 (글자 시작 − 면 왼쪽)과 같게 해서 버튼 글자가 기준선에 떨어지게 한다.
     - 아이콘 열을 두려면 모든 행에 둔다.
   - 선과 상자
     - 선은 열 경계와 머리 줄 아래, 두 종류뿐이다.
     - 구역은 선이 아니라 여백과 구역 제목으로 나눈다.
     - 카드는 실제 묶음에만 쓴다(0~1개가 기본).
   - 정보 예산
     - 영역마다 질문 하나를 적는다(예: 목록 "누구를 볼까", 상세 "무엇을 알고 근거는 무엇인가").
     - 같은 정보는 화면에 한 번만 둔다. 역할이 다른 두 곳에 남길 때는 그 이유를 적는다.
     - 범위·수·상태는 예외일 때만 보인다. 수가 모두 같으면 하나만 쓰고, 정상 상태에는 태그를 붙이지 않는다.
     - 개발용 표시(ID·내부 용어·"가정" 알약)는 화면에서 뺀다.
     - **뺀 정보가 지금 어디서 보이는지 표로 적고, 핵심 과업을 끝까지 해 본다**. 빼다가 과업이 막히면 그것은 결함이다.
   - 위계
     - 글자 크기 3종, 굵기 2종, 글자색 3종(본문·보조·강조)과 상태색만 쓴다.
     - 강조색은 선택 표시와 주요 행동, 두 곳에만 쓴다.
     - 데이터 범례색(유형 색)은 강조색 규칙과 별개다. 다만 그 위에 강조색으로 선택을 표시하면 명도 대비를 잰다. 약하면 색이 아닌 표시(크기·굵기·나머지 흐리게 등)를 더한다.
   - 부품
     - 버튼은 solid를 맥락당 한 번, 그 밖에는 soft·ghost를 쓴다.
     - 모서리 토큰은 두 개(조작·면)다.
     - 보이는 높이와 누르는 영역을 나눈다(정밀 포인터에서만 낮게 보이고, 누르는 영역은 44 유지).
     - 아이콘은 공개 아이콘 세트 하나만 쓴다(손으로 그린 path 금지). 버전과 라이선스를 적는다.
   - 그래프·도표 화면에서 확인할 것: 라벨이 선과 겹치는지, 무리 제목이 자기 무리 옆에 있는지, 선택 표시가 이중 링·그림자 없이 보이는지.
2. **정돈 점검** (같은 파일 "점검" 절, SKILL.md 2·5절에서 부름)
   - ego lite로 상태·폭마다 다음을 잰다.
     - 영역별 면 왼쪽·글자 시작·오른쪽 끝 x의 고유 값 개수(0.5px 안이면 같은 값)
     - 머리 줄의 top·높이·아래 선 y
     - 간격이 단계 값인지
     - 태그·알약 수, 같은 문자열의 반복, 글자 크기·굵기 종류, 강조색을 쓴 요소 수와 위치
   - 전과 후를 같은 방법으로 재서 표로 남긴다. 측정은 읽기 전용 스크립트로 반복할 수 있게 하고, 측정 결과만으로 합격이라고 하지 않는다.
   - 사람 눈 점검: 3초 첫인상에서 시선이 선택한 대상에 먼저 가는지, 한 영역에서 시선을 끄는 것이 둘 이상인지 본다.
   - 독립 검토: 작성자와 다른 모델에게 원래 요구, 화면 경로, 레퍼런스만 준다. 검토자는 첫인상 → 정렬 실측 → 정보(남은 중복 / 너무 빼서 막힌 과업) → 부품 → 고칠 것 최대 10개(문제 → 근거 좌표 → 정확한 값)를 보고한다. 새 장식을 더하는 수정에는 무엇을 대체하는지 쓰게 한다.
3. **예시 화면으로 고르기** (같은 파일 "고르기" 절, system.md 방향 선택과 SKILL.md 1절에서 연결)
   - UI 선택지(높이, 색 방식, 선택 표시, 배치 등)는 글로만 묻지 않는다.
   - 선택지마다 화면에 스위치를 두지 않는 쿼리를 만든다. 같은 상태·폭·데이터로 캡처해 라벨을 붙여 나란히 붙인 비교 이미지를 만든다. 작은 차이는 같은 부위를 확대해 자른다. 색이 쟁점이면 흑백판을 하나 더 둔다.
   - 작성자가 이미지를 직접 확인한 뒤에 이미지 경로와 차이 설명(무엇이 같고 무엇만 다른지)을 함께 묻는다. 추천에는 이유를 붙인다.
   - 고른 결과는 프로필에 고정하고, 버린 쪽은 비교용 쿼리로만 남긴다.
4. **SKILL.md 연결**: 1절(고를 때 예시 화면), 2절(기존 화면 정돈 점검), 3절(정돈 규칙으로 구성, 진단 표에 "정보 나열·선 끝 어긋남" 행), 5절(측정 전후표 + 독립 검토)에 한 줄씩 넣는다. SKILL.md 길이는 90줄 이하로 둔다.
