# 자리 비움 2단계 — 메뉴 막대 앱, 멈춤 3가지 해결

## 목표
사용자가 상단바 앱에서 끝 시각을 고르고 자리를 뜨면, 그 시각까지 에이전트가 **멈추지 않고 실제로 일을 끝낸다**. 아침에 패널에서 무엇이 실행됐고 무엇이 보류됐는지 본다.
1단계(0.22.0) 뒤에도 남은 멈춤 셋을 없앤다 (사용자: "이 경우를 해결할 수 있어야 이 어플을 만드는 목적이 있어"):
1. 글 속의 `cdk deploy`를 guard가 배포 명령으로 오인
2. 에이전트가 질문 창 또는 글로 묻고 턴을 끝냄
3. 배포가 되어야 다음 일이 가능한 작업

## 승인 (사용자, 2026-11-26)
- "3번까지 진행하자" → 아래 S1~S4 구현까지 승인. **1단계의 "권한을 넓히지 않는다"를 바꾼다**: 사용자가 떠나기 전에 준 배포 티켓 안에서는 사람이 보지 않은 코드가 배포된다 (위험은 "엣지 케이스 & 리스크").
- guard 전체 끄기 스위치는 두지 않는다. push·본체 pull은 사용자 확인 뒤 (이 작업에서 하지 않음).
- 이 작업에서 실제 AWS 배포는 실행하지 않는다 (가짜 `cdk`로 시험). 첫 실제 사용은 사용자가 한다.
- 자동 배포: 정책 밖 (이 레포는 push가 배포 아님, push하지 않음).

## 범위
- **포함**: guard 판정 개선(오탐·미탐), `away.py` 확장(질문 보류, 조건부 재개, 세션 기록, 티켓), 새 `scripts/away_deploy.py`(CDK 티켓 실행기), `hooks.json`(AskUserQuestion·Stop), `macos/`(SwiftUI 메뉴 막대 앱 + 빌드·설치 스크립트), 시험, harness·README·CLAUDE.md, 0.23.0
- **제외**: CDK가 아닌 배포(terraform, amplify, deploy.sh, 배포가 되는 push)의 티켓, 자동 롤백·재배포, 사용량 한도·로그인 만료 복구, 앱 배포(공증·Developer ID), 윈도우·리눅스 앱, Write·Edit matcher

## 동작 (사용자 관점)
1. 상단바 아이콘 → 패널에서 끝 시각(30분·1시간·2시간·3시간·아침 8시·직접)과, 필요하면 배포 티켓(레포 + 스택, 기본 1회)을 고르고 "자리 비움 시작".
2. 그 시각까지
   - 확인이 필요한 명령은 거절 + 아침 목록 (1단계 그대로). 글 속 단어는 더 이상 걸리지 않는다.
   - 질문 창은 뜨지 않고 보류 목록에 적힌다. 글로 묻고 끝낸 탭은 최대 2번 "기본값으로 정하거나 보류하고 계속하라"로 이어진다.
   - 티켓이 있는 스택은 전용 실행기가 테스트·`cdk diff` 검사를 통과하면 배포한다. 삭제·교체·IAM 변경이 보이면 배포하지 않는다.
3. 돌아와서 패널: 실행된 배포(결과), 거절된 명령, 보류된 질문, 탭별 마지막 활동.

## 설계

### S1. guard 판정 (`scripts/guard.py`)
- 원인: `RULES`를 명령 전체 글자에 `re.search`하고, 다른 규칙은 따옴표·heredoc을 모르는 `re.split`으로 나눈다.
- 새 해석기 `shell_segments(command)`: 따옴표, 이스케이프, heredoc(`<<`, `<<-`, 따옴표 구분자), `$(…)`·백틱·`( … )`·`{ … }` 중첩, 연산자(`&&` `||` `;` `|` `&` 줄바꿈)를 읽어 세그먼트 목록을 낸다. 세그먼트 = 단어 목록 + 원문 + heredoc 본문 + 다음 세그먼트로 파이프 여부. 중첩(`$(…)`, `sh -c '…'`, 셸에 넣는 heredoc)은 안쪽을 다시 해석해 목록에 더한다.
- **데이터로 확인된 것만 뺀다** (Codex 반박): 실행하지 않는 명령 목록(`echo printf cat grep rg ls head tail wc mkdir touch tee` , `git commit|tag|log|show|diff|grep|add|status|notes`, `gh`, `orca`)의 인자와 그 heredoc 본문만 판정에서 뺀다. 그 밖의 세그먼트는 지금처럼 원문을 검사한다. 뺀 인자 안의 `$(…)`·백틱은 실행되므로 따로 검사한다. 데이터 세그먼트가 필터(`grep head tail wc sort uniq tee cat jq sed tr cut less`)가 아닌 명령으로 파이프되면(`… | sh`, `| xargs`) 빼지 않는다.
- 미탐 보강 (agy 실측): `cdk`·`terraform`은 단어 기준으로도 본다 (`cdk --profile prod deploy`, `terraform -chdir=infra apply`). `deploy_reasons`·`push_reasons`·`record_reasons`·`away_reasons`·`dangerous_rm`은 새 세그먼트를 쓴다 (`(cd infra && ./deploy.sh)`, `$(./deploy.sh)`, `bash -c "echo \"go\" && ./deploy.sh"`).
- 해석 실패(닫히지 않은 따옴표 등)면 예전 방식(전체 원문 검사)으로 돌아간다 (fail-safe).
- 시험: `test_guard.sh`에 오탐(→ `none`)·미탐(→ `ask`, 자리 비움 중 `deny`) 대칭 표.

### S2. 질문 보류·조건부 재개·세션 기록 (`scripts/away.py`, `hooks/hooks.json`)
- `hooks.json`: PreToolUse matcher `AskUserQuestion` → `away.py hook`, 새 `Stop` → `away.py hook` (timeout 5). `hook`은 `hook_event_name`으로 갈린다.
- **질문 창**: 모드가 유효하면 `deny` + "사용자는 HH:MM까지 없습니다. 되돌릴 수 있으면 기본값으로 정해 기록하고, 아니면 보류 목록에 남겼으니 다른 일을 계속하세요". 질문 요지(가림, 300자)를 `holds.jsonl`에. 꺼져 있으면 출력 없음.
- **턴 종료(Stop)**: 아래를 모두 만족할 때만 `{"decision":"block","reason":…}`:
  모드 유효, `stop_hook_active` 아님, 서브에이전트·Orca 워커 아님, 마지막 응답이 질문·확인 대기 신호(끝부분의 `?`, "할까요/해 주세요/알려 주세요/승인/기다리", "Should I/let me know/waiting")를 가짐, 이 세션의 이번 회차 재개 < 2회, 직전 재개 뒤 진전 있음(대화 기록에 도구 호출 3건 이상).
  막을 때 마지막 응답 요지를 `holds.jsonl`에 `kind: stop`으로 남긴다. 그 밖에는 통과.
- **세션 기록** `away/sessions/<session_id>.json`(세션마다 파일 하나, 잠금 없음): `{session, cwd, repo, transcript, last_event, last_event_ts, blocks, block_size, state_id}`. SessionStart·UserPromptSubmit·Stop·질문 거절 때 갱신. 마지막 활동 시각은 대화 기록 파일의 mtime으로 읽는다 (도구 호출마다 훅을 돌리지 않는다).
- 계약 확장 (기존 키 유지): `status --json`에 `holds_count`, `tickets`, `sessions:[{session, repo, cwd, last_event, last_event_at, last_activity_at}]`. `report --json`에 `holds:[{ts, kind, repo, session, text}]`, `runs`(S3). `report --clear`는 holds·runs도 비운다. 앱은 탭 상태를 "완료/멈춤"으로 단정하지 않고 마지막 이벤트와 시각만 보여 준다 (Codex).
- **구현 전 실측** (더미 플러그인, 대화형 bypass 탭): AskUserQuestion `deny` 뒤 창 없이 계속되는가 / Stop 입력에 `last_assistant_message`·`stop_hook_active`가 오는가(없으면 대화 기록 끝을 읽는다) / Orca 워커를 가르는 환경 변수 / `worker_done` 뒤 Stop이 불리는가. 결과를 아래 표에 적고 설계를 맞춘다.

### S3. 배포 티켓 (`scripts/away.py`, 새 `scripts/away_deploy.py`)
- 티켓은 `state.json` 안에 산다 → 끝 시각·`off`와 함께 사라진다: `tickets:[{id, repo, stack, limit, used, locked, note}]`. `away.py on … --ticket '<레포 경로>::<스택>[::횟수]'`(여러 번). 횟수 기본 1, 최대 3.
- 후보: `away.py request --stack <스택> [--note …]`(에이전트가 떠나기 전 "이 작업에 필요한 배포"를 `requests.jsonl`에 적음)와 최근 아침 목록의 거절된 `cdk deploy`. `status --json`의 `ticket_candidates`로 앱이 체크박스를 만든다. 후보는 권한이 아니다.
- 실행기 `away_deploy.py run --stack <스택> [--cwd <cdk 앱 폴더>]` (에이전트가 Bash로 부른다. `cdk`는 실행기가 직접 띄우므로 guard를 거치지 않는다):
  1. 유효한 모드 + 같은 레포(worktree면 공통 git 폴더 기준)·스택의 티켓, `used < limit`, 잠기지 않음. 아니면 끝 코드 3 + 아침 목록.
  2. 프로필 `테스트` 줄의 명령(있으면) 통과. 없으면 `checks`에 "테스트 없음"으로 기록하고 진행.
  3. `cdk diff <스택>`(실패하면 중단). 출력에 리소스 삭제(`[-]`), 교체(`replace`·`requires replacement`·`may be replaced`), IAM·보안 그룹 변경 표가 있으면 배포하지 않는다 (끝 코드 4).
  4. 잠금 안에서 `used += 1`을 먼저 저장하고 `cdk deploy <스택> --require-approval never` 한 번. 실패·시간 초과면 티켓 `locked`. 재시도·롤백 없음.
  5. 결과를 `runs.jsonl`에: 시각, 레포, 스택, 단계별 결과, diff 요약(추가·수정 수), 끝 코드, 로그 경로(`away/logs/`, 0600).
  - `cdk` 실행 명령은 `npx cdk` (티켓 `cdk` 필드로 바꿀 수 있음). `destroy`·다른 스택·추가 인자는 받지 않는다.
- guard: `away.py … --ticket`·`away_deploy.py` 밖에서 away 폴더를 건드리는 명령은 계속 확인 대상. 에이전트가 `--ticket`으로 스스로 켜는 명령은 확인 대상(자리 비움 중이면 거절)으로 추가.
- harness: 인프라 T2 승인은 티켓 범위(레포·스택·횟수·끝 시각)로 받은 것으로 본다. 티켓 밖 배포는 그대로 거절·보류.

### S4. 메뉴 막대 앱 (`macos/`)
- SwiftPM 패키지 `AwayBar`: 라이브러리(`AwayCore`: JSON 모델, kit 찾기, 명령 실행, 끝 시각 계산) + 실행 파일(SwiftUI `MenuBarExtra`, `.window` 패널) + 테스트(`swift test`). macOS 14 이상.
- kit 찾기: 저장된 경로 → `~/.claude/plugins` 설치 기록의 `kit@37writes` → `~/Documents/dev/37writes-claude-kit` → 못 찾으면 폴더 선택 한 번. Python은 `/usr/bin/python3` 등 절대 경로를 셸 없이 실행하고, 유효한 JSON과 `ok`까지 확인한다 (`py.sh`는 Python이 없어도 0으로 끝난다).
- 상단바: 꺼짐이면 아이콘만, 켜짐이면 아이콘 + 남은 시간. 패널: 끝 시각 버튼·시각 선택, 전원·뚜껑(배터리·닫힘이면 시작 버튼 대신 이유), 배포 티켓 후보 체크 + 직접 추가, 시작/끄기, 탭별 마지막 활동, 실행된 배포·거절된 명령·보류된 질문(비우기), 로그인 시 실행(앱만 열림, 모드는 켜지 않음), 종료.
- 화면 시안은 구현 뒤 실제 캡처를 보여 준다 (패널형은 이미 고름).
- `macos/install.sh`: `swift build -c release` → `.app` 묶음(Info.plist `LSUIElement`) → 서명(Apple Development 인증서, 없으면 ad-hoc) → `~/Applications/AwayBar.app`.

## 결정 & 이유
- **훅은 남기고 원인마다 따로 푼다** → 훅을 없애면 배포 하나를 풀려다 모든 확인이 사라진다.
- **티켓 실행은 guard의 allow가 아니라 전용 실행기** → guard 훅은 15초 안에 테스트·diff를 돌릴 수 없고, 실행기가 대상·횟수·검사를 한 곳에서 강제한다. guard 규칙은 그대로라 티켓 밖 `cdk deploy`는 계속 거절된다.
- **마지막 활동은 대화 기록 mtime** → 도구 호출마다 Python을 띄우지 않는다.
- **앱은 `away.py` JSON만 부른다** → 판정·가림·잠금을 두 곳에 만들지 않는다 (1차 의견).

## 엣지 케이스 & 리스크
- 티켓 스택에는 테스트·diff 검사를 통과한 런타임 버그가 밤사이 배포될 수 있다. 자동 롤백은 없다.
- 같은 UID라 에이전트가 티켓을 스스로 만드는 것을 증명 가능하게 막지 못한다 (harness 규칙 + guard best-effort).
- 질문 신호는 글자 휴리스틱이다: 물음표 없는 대기는 놓치고, 완료 보고의 물음표로 한 턴이 더 돌 수 있다 (세션당 2회 상한).
- `cdk diff` 출력 형식이 CDK 버전에 따라 다를 수 있다 → 해석하지 못한 형식은 배포하지 않는 쪽.
- 파일에 쓰는 글(`cat > x.sh <<EOF`)은 이제 걸리지 않는다. 그 파일을 나중에 실행하는 것은 예전부터 guard가 보지 못하는 경로다 (Write 도구로 쓴 스크립트와 같다).
- 로컬 서명 앱의 로그인 시 실행(`SMAppService`)이 안 되면 LaunchAgent plist로 대신한다.
